## 错误：找不到 angular.json 文件（No angular.json file found）

Storybook 既可以部署在单项目 Angular 工作区，也支持多项目工作区。要为某个项目配置 Storybook，请在 `angular.json` 文件所在的工作区根目录运行[安装命令](./get-started/install.mdx)。初始化过程中会创建 `.storybook` 文件夹，并编辑 `angular.json` 文件，为所选项目加入 Storybook 配置。务必在根目录层级运行该命令，以确保 Storybook 能正确检测所有项目。

## 如何用 Create React App 运行覆盖率测试并排除 stories？

Create React App 不允许在 `package.json` 中为 Jest 提供选项，但你可以通过命令行参数运行 `jest`：

```sh
npm test -- --coverage --collectCoverageFrom='["src/**/*.{js,jsx}","!src/**/stories/*"]'
```

<Callout variant="info" icon="💡">

如果你使用 [`Yarn`](https://yarnpkg.com/) 作为包管理器，需要相应调整命令。

</Callout>

## Storybook main 配置中的无扩展名导入

在升级或运行 Storybook 时，你可能会看到关于 `.storybook/main.<js|ts>` 中无扩展名相对导入的警告（例如：`import sharedMain from '../main'`）。
Storybook 要求配置文件中的导入显式携带扩展名，以避免这一弃用警告。

要修复该问题，只需确保导入的文件（TypeScript 或 JavaScript）带上扩展名：

```ts title=".storybook/main.<js|ts>"
// Change from this 👇
import sharedMain from '../main';

// To this 👇
import sharedMain from '../main.js'; // or .ts
```

### 针对 TypeScript 用户（`.storybook/main.ts`）

你还需要配置 TypeScript，让这些导入可以类型检查而不产出 JavaScript：

```json title=".storybook/tsconfig.json"
{
  "extends": "<path-to-your-main-tsconfig>",
  "compilerOptions": {
    "moduleResolution": "bundler",
    "allowImportingTsExtensions": true,
    "noEmit": true
  }
}
```

<Callout variant="info">

建议单独添加一个 `.storybook/tsconfig.json` 文件，这样这些改动只会作用于 Storybook 配置文件，而不会影响整个项目。

</Callout>

## 为什么没有 addons channel？

一个常见错误是 addon 尝试访问 "channel"，但 channel 尚未设置。它可能发生在以下几种情况：

1. 你在非浏览器环境（如 Jest）中尝试访问 addon channel（例如调用 `setOptions`）。你可能需要添加一个 channel mock：

   ```js
   import { addons, mockChannel } from 'storybook/preview-api';

   addons.setChannel(mockChannel());
   ```

2. 在 React Native 中属于特殊情况，参见 [#1192](https://github.com/storybookjs/storybook/issues/1192) 的说明

## 为什么 addon 在组合（composed）的 Storybook 中不工作？

Composition 是我们随 6.0 版本发布的新功能，目前仍有一些限制。

目前，你在组合 Storybook 中使用的 addon 无法正常工作。

我们正在努力克服这一限制，很快你就可以像使用非组合 Storybook 一样使用它们了。

## 可以拥有一个没有本地 stories 的 Storybook 吗？

除非项目中至少定义了一个本地 story（或文档页面），否则 Storybook 无法工作。这里的“本地”指的是在项目 `.storybook/main.js` 配置中引用的 `.stories.*` 或 `.mdx` 文件。

如果你处于 [Storybook composition](./sharing/storybook-composition.mdx) 场景中——拥有多个 Storybook，并想再建一个自身没有 stories 的 Storybook，作为项目内所有其他 Storybook 的“粘合剂”用于演示/文档目的——可以按以下步骤操作：

引入一个单独的 `.mdx` 文档页（需要 addon-docs），作为介绍页，如下所示：

## 哪些社区 addon 与最新版本的 Storybook 兼容？

从 Storybook 6.0 开始，我们引入了一些旨在简化开发工作流的出色特性。

同时我们想提醒：如果你计划使用社区创建的 addon，需要注意其中一些可能是针对旧版本 Storybook 开发的。

我们正在积极提供更好的方式来处理这一情况，但在此期间，希望你能保持谨慎，以免遇到意外问题。欢迎在下面的 [GitHub issue](https://github.com/storybookjs/storybook/issues/26031) 中留言，帮助我们收集信息，扩充需要更新才能兼容最新版 Storybook 的 addon 列表。

## 我在 Storybook 生产构建上看到 "No Preview" 错误

如果你使用 `serve` 包来验证 Storybook 的生产构建，就会遇到这个错误。它与 `serve` 处理重写（rewrite）的方式有关。例如，`/iframe.html` 会被重写为 `/iframe`，于是你就会看到该错误。

我们建议改用 [http-server](https://www.npmjs.com/package/http-server)，并使用以下命令预览 Storybook：

```shell
npx http-server storybook-static
```

<Callout variant="info">

如果你不想频繁运行上面的命令，可以把 `http-server` 加为开发依赖，并创建一个新脚本来预览 Storybook 的生产构建。

</Callout>

## 为什么我的代码块在 Storybook MDX 中没有语法高亮？

开箱即用，Storybook 为一组语言（如 Javascript、Markdown、CSS、HTML、Typescript、GraphQL）的代码块提供语法高亮。目前，尝试注册自定义语言以获得语法高亮存在一个已知限制。我们正在修复，可用后会更新本节。

## 为什么我的 MDX 样式在 Storybook 中不生效？

用 MDX 编写文档可能比较麻烦，尤其是代码在代码块中换行时的格式处理。例如，这样写会出问题：

```mdx title="Example.mdx"
<style>{`
  .class1 {
    ...
  }

  .class2 {
    ...
  }
`}</style>
```

但这样写没问题：

```mdx title="Example.mdx"
<style>
  {`
    .class1 {
      ...
    }

    .class2 {
      ...
    }
  `}
</style>
```

更多信息参见这个 [issue](https://github.com/mdx-js/mdx/issues/1945)。

## 为什么我的 GraphQL mock 查询在 Storybook 的 MSW addon 中失败？

如果你使用 Vue 3，需要安装 [`@vue/apollo-composable`](https://www.npmjs.com/package/@vue/apollo-composable)。

使用 Svelte 时，需要安装 [`@rollup/plugin-replace`](https://www.npmjs.com/package/@rollup/plugin-replace)，并把 `rollup.config` 文件更新为如下内容：

```js title="rollup.config.js"
// Boilerplate imports

import replace from '@rollup/plugin-replace';
const production = !process.env.ROLLUP_WATCH;

// Remainder rollup.config implementation

export default {
  input: 'src/main.js',
  output: {
    sourcemap: true,
    format: 'iife',
    name: 'app',
    file: 'public/build/bundle.js',
  },
  plugins: [
    // Other plugins

    // Configures the replace plugin to allow GraphQL Queries to work properly
    replace({
      'process.env.NODE_ENV': JSON.stringify('development'),
    }),
  ],
};
```

使用 Angular 时，最常见的问题是 `mockServiceWorker.js` 文件的放置位置。请参考这个[示例](https://github.com/mswjs/examples/tree/main/examples/with-angular)。

不可以。目前 MSW addon 只支持 GraphQL 查询。如果你希望加入该功能，请到 [MSW addon 仓库](https://github.com/mswjs/msw-storybook-addon)提交 issue 并与维护者跟进。

## 为什么使用某些字符时，我的 stories 不能正确显示？

Storybook 允许你在命名 story 时使用大多数字符。但某些特定字符（如 `#`）可能导致 Storybook 生成 story 内部标识符时出现问题，造成冲突，进而无法正确输出目标 story。建议尽量少用这类字符。

## 为什么 Storybook 的 source loader 对柯里化函数返回 undefined？

这是 Storybook 的一个已知问题。如果你希望它被修复，请附上一个[可复现的示例](./contribute/how-to-reproduce.mdx)提交 issue，以便分类处理并在未来版本中修复。

## 为什么 Storybook 的 test runner 不工作？

Storybook 的 test runner 与最新版 Jest（即 28 版）存在兼容问题，导致它无法有效运行。变通办法是把 Jest 降级到上一个稳定版（即 27 版），即可正常运行。更多信息参见这个 [issue](https://github.com/storybookjs/test-runner/issues/99)。

## Storybook 如何处理环境变量？

Storybook 内置了对[环境变量](./configure/environment-variables.mdx)的支持。默认情况下，环境变量只在 Node.js 代码中可用，在浏览器中不可用——因为有些变量应当保密（例如 API 密钥），**不应**暴露给访问已发布 Storybook 的任何人。

要暴露某个变量，必须在其名称前加 `STORYBOOK_` 前缀。这样 `STORYBOOK_API_URL` 在浏览器代码中可用，而 `API_KEY` 则不可用。此外，你还可以通过在 `.storybook/main.js` 文件中设置 [`env`](./configure/environment-variables.mdx#using-storybook-configuration) 字段来自定义哪些变量被暴露。

变量在 JavaScript 编译时（即启动开发服务器或构建 Storybook 时）被写入。环境变量文件不应提交到 Git，因为它们通常包含不宜入库的机密。请改为把 `.env.*` 加入 `.gitignore` 文件，并在托管平台上手动设置环境变量（例如 [GitHub](https://docs.github.com/en/actions/security-guides/encrypted-secrets#creating-encrypted-secrets-for-a-repository)）。
