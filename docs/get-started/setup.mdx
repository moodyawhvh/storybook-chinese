## 渲染组件样式

Storybook 对你如何生成或加载 CSS 没有强约束。它只渲染你提供的 DOM 元素。但有时，开箱即用的效果会“看起来不对”。

你可能需要为 Storybook 的渲染环境配置 CSS 工具链。以下是社区流行工具的一些配置指南。

- [Tailwind](https://storybook.js.org/recipes/tailwindcss/)
- [Material UI](https://storybook.js.org/recipes/@mui/material/)
- [Vuetify](https://storybook.js.org/recipes/vuetify/)
- [Styled Components](https://storybook.js.org/recipes/styled-components/)
- [Emotion](https://storybook.js.org/recipes/@emotion/styled/)
- [Sass](https://storybook.js.org/recipes/sass/)
- [Bootstrap](https://storybook.js.org/recipes/bootstrap/)
- [Less](https://storybook.js.org/recipes/less/)
- [Vanilla-extract](https://storybook.js.org/recipes/@vanilla-extract/css/)

没找到你要的工具？查看[样式与 CSS](../configure/styling-and-css.mdx) 页面了解更多细节。

## 为你的技术栈配置 Storybook

Storybook 自带宽松的[默认配置](../configure/index.mdx)，会尽量自我调整以适配你的环境，但并非万无一失。

你的项目可能有一些额外要求，组件才能被隔离渲染。这就需要进一步定制配置。你可能需要的配置大致分为三类。

<details>
<summary>构建配置（Webpack 与 Babel 等）</summary>

如果你运行 `yarn storybook` 时在 CLI 中看到报错，很可能需要修改 Storybook 的构建配置。可以尝试以下做法：

- [预设（Presets）](../addons/addon-types.mdx)把各种技术的常见配置打包进 Storybook。特别是，Create React App 和 Ant Design 都有现成的 preset。
- 为 Storybook 指定自定义 [Babel 配置](../configure/integration/compilers.mdx#babel)。只要可行，Storybook 会自动尝试使用你项目的配置。
- 调整 Storybook 使用的 [Webpack 配置](../builders/webpack.mdx)。如有需要，尝试并入你自己的配置。

</details>

<details>
<summary>运行时配置</summary>

如果 Storybook 构建成功，但在浏览器中一连接就报错，多半是某个输入文件没有正确编译/转译为浏览器可解释的代码。Storybook 支持常青（evergreen）浏览器，但你可能需要检查 Babel 和 Webpack 设置（见上文），确保组件代码能正常工作。

</details>

<details id="component-context" name="component-context">
<summary>组件上下文</summary>

如果某个特定 story 渲染有问题，往往意味着你的组件期望某个特定环境对组件可用。

前端的一种常见模式是：组件假定自己渲染在渲染层级上层父组件提供的特定“上下文”中（例如主题 provider）。

<If renderer={[ 'react', 'preact', 'react-native', 'solid' ]}>

## 加载静态资源

我们建议通过 Storybook 静态地提供组件请求的外部资源和静态资产。这能确保你的 stories 始终能访问到这些资源。阅读我们的[文档](../configure/integration/images-and-assets.mdx)了解如何在 Storybook 中托管静态文件。
